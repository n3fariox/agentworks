# Test fixture cleanup audit

Audit base: `b8845a7` (assigned branch `feature/side-panel-test-cleanup`). No production files changed.

## Side-panel reproduction

Built this worktree with `cargo build --locked --offline` and ran the named Playwright test against a new loopback server, catalog, SQLite database and demo-state directory, with this worktree as its allowed root. The unmodified test failed four out of four runs at the inline-image assertion (formerly line 371). The first `#session-files` click opened `#side-panel` on every run: the specifically reported initial-click failure was not reproduced against this build.

Commit `e77b253` deliberately changed inline Markdown images to open the accessible image viewer (`setupChatReferences` calls `imageViewer.decorate`). The old side-panel test still expected an inline-image click to open Files. It now checks the viewer, closes it, and explicitly reopens Files before exercising panel resizing. File links still exercise the panel. The complete desktop/phone scenario passes five repeated runs after the fix. `create()` also waits for its dialog to close and its requested session heading before accepting Ready, which otherwise can describe the previous active session.

## Confirmed cleanup issues fixed

- **Browser session tests:** the side-panel directory was never removed, including on assertion failures. It now has a `finally`. Session/project teardown previously swept every title beginning with `Browser test`, potentially deleting another run's fixtures, and depended on JavaScript in the page still working. Responses now identify this test's own created resources (including imported sessions, automation definitions and automation-run sessions); teardown uses the independent request fixture with an explicit Origin and checks deletion responses.
- **Input queue:** the suite and its restart/fault subtests retained their directories/databases. Server shutdown was fire-and-forget; readiness and the first half of the restart test ran outside the cleanup guard. The SQLite fault connection and manually created browser context were only closed on success. Cleanup now covers those failure paths, awaits child shutdown, and removes the roots after stopping the servers.
- **Mentions / work logs:** mentions did not remove its fixture and did not await its server. Work logs retained its fixture and reused a destructive fixed path. Both now await shutdown and remove their roots; work logs uses a unique directory.
- **Palettes:** replaced the fixed, pre-emptively removed fixture directory with a unique directory and updated directory-search assertions accordingly. Shutdown is bounded and awaited.
- **Verification:** fixed per-port databases/catalogs/demo histories persisted across invocations. Each invocation now owns a unique fixture root, an explicit loopback bind and allowed root. Its finalizer terminates its own WebSocket, awaits server shutdown and removes the root even when a child check fails.
- **Standalone smoke tests:** 18 scripts allocated unique temporary roots but never removed them. Their existing outer `finally` blocks now remove the root after their existing browser/client/server teardown. This also removes their isolated Git repositories, branches/worktrees, demo histories and SQLite companions. `AGENTWORKS_KEEP_TEST_FIXTURES=1` deliberately retains diagnostic/native-import fixtures; the README documents that opt-in. No pre-existing fixture directories are swept.
- **Port ownership:** the quota-status smoke shared default 4491 with communication-defaults. Moving the validation run to 4492 collided with inbox-settings instead: it accepted the other server’s readiness response and wrote fixtures into the wrong store. Quota-status now defaults to dedicated 4493. The affected browser startups, other touched server fixtures, permission-mode smoke and verifier verify `/api/service/restart` PID against their owned child before using a port. A regression test rejects a different PID before any mutations.
- **Permission-mode smoke startup:** the default executable referenced a transient `.cache` build. A missing binary led to an unsettled top-level await in shutdown, bypassing directory removal (confirmed by the first audit run). It now defaults to `target/debug/agentworks`, observes spawn errors/early exit, and uses bounded teardown that handles absent or already-exited children. A normal rerun passed; an injected missing binary exited 1 promptly and removed its newly created fixture.
- **MCP wire / native import:** MCP wire now awaits its spawned stdio processes and mock bridge shutdown. Native import closes its read-only SQLite connection immediately after reading fixtures, including on parse/query failure.

`tests/support/cleanup.mjs` supplies bounded awaited child termination (SIGKILL fallback), safe repeated cleanup, and explicit smoke retention. Five Node regression tests cover assertion-failure cleanup, a SIGTERM-ignoring child, retention versus default removal, failed spawn teardown, and refusal to accept a different PID on a test port.

## Scope and remaining constraints

Reviewed the repository's browser suites, Node smoke/unit checks, Rust test fixture allocation/removal, and Python supervisor tests. Existing suites with unique fixtures and awaited shutdown/removal were left alone. Playwright owns ordinary page/context storage, cookies and service workers; the manually created queue context needed an explicit failure-safe close. Rust tests generally remove their temporary databases/catalogs on success, and the inbox fixture uses Drop; converting all panic paths to a new fixture framework is outside this patch. Python supervisor tests already use TemporaryDirectory and process teardown.

Dedicated fixed test ports remain. Run the verifier serially against other invocations of the same suites; their ports do not support concurrent full verifier jobs. The confirmed quota-status collision was fixed with default 4493 and PID ownership checks in the affected fixtures. Changing every server/Origin/baseURL contract was deferred. Tests that intentionally target an external server can leave catalog location records/provider history retained by the application's deletion semantics; use the isolated verifier for a disposable full run. Native-provider inference/import checks are opt-in and were not run; those providers also retain their own external history according to their CLI semantics. Cleanup cannot run after SIGKILL of the test runner itself. Existing failure reports/screenshots remain intentional artifacts.

The initial focused expansion also exposed an image-viewer focus-restoration failure in `tests/chat-references.spec.mjs`; production changes for that independent behavior are outside this request. It passed in the final full run.
