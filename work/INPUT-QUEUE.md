# L-05 activity indicators and queued explicit inputs (batch 007 worker)

- Server: `src/input_queue.rs`. Queue state persists as `SessionData.input_queue` (serde default) via the existing session-state save, so there is no table or schema-version change. Queue changes are saved with `save_state` and broadcast as an unsequenced `input_queue` websocket event, so they don't consume the bounded transcript history.
- Limits: 20 pending items, 64 KB pending total, 32 KB per item, 100-char request IDs; only the last 5 sent items are kept.
- Identity: each enqueue `requestId` is bound to its exact original payload in the module-owned `input_queue_bindings` table (created at startup with `CREATE TABLE IF NOT EXISTS`; cascades on session delete; no schema version change). The binding is inserted in the same SQLite transaction as the queue state save. Bindings survive edit, remove, send, display pruning and restart. They are capped at 1000 IDs / 4 MB per session, and when full a new enqueue is refused rather than old IDs being evicted. Retrying the original payload returns a duplicate and any other payload returns 409, both on the queue route and on the direct prompt route. An ID already sent directly cannot be queued. Dispatch request ID is `queue:{id}:r{revision}`. Edits need the current revision and are refused once the item is claimed.
- Persistence: every queue API mutation runs under `run_lock`, is saved with `save_state` before it is acknowledged, and is rolled back with an error response if the save fails.
- Dispatch: the runtime only calls `record_outcome`. A clean `end_turn` sets `ready`; a status-only `/usage` or `/status` probe turn never does. Cancel, timeout, error, quota continuation (`continuation.limited`/`due_at`) and storage failure mark the in-flight item `error` (never resent) and pause the queue. `input_queue::scheduler` (250 ms tick, same communication/run/workspace locks and `allow_start` drain gate as the limit-resume scheduler) dispatches only when the session is idle, not suspended, has no storage error and no quota pause. It persists the `sending` claim first, then calls the shared `accept_prompt` used by direct prompts. B-02's `continuation.begin_turn` belongs in `accept_prompt`, so it applies at dispatch, not at enqueue.
- Stop, Suspend and completion reports call `Queue::block`, which clears `ready` and keeps a pause even when the queue is empty or the turn later reports `end_turn`, so they win any turn-end race. `has_pending` also counts unresolved `error` items. The scheduler and resume re-check `checked_cwd` (roots) before dispatching. Resume (`POST /queue/resume`) checks drain, suspend and quota before persisting, then dispatches deliberately when idle.
- Restart: `recover()` turns `sending` into `error` (delivery unknown) and pauses the queue. Nothing is replayed.
- The internal `queued_prompt` (automation/handoff) is untouched.
- Frontend: one stable pending identity per session (sessionStorage `agentworks-pending-sends`), shared by Send and Queue. If a direct send gets a 409 because the session became busy, the client enqueues the same request ID. The draft is cleared only after acceptance.
- Deferred: native-command validation before dispatch (beyond the root, drain, suspend, quota and storage gates), and wiring B-02 `begin_turn` into `accept_prompt` (coordinator integration).
- Not covered end to end: timeout (minimum policy values are 60 s) and restart drain (needs a supervised restart setup); these are covered by unit tests and code-level gates only.
- Routes: `GET/POST /api/sessions/{id}/queue`, `PATCH/DELETE /api/sessions/{id}/queue/{item}`, `POST /api/sessions/{id}/queue/resume`.
- Integration hooks: `input_queue::has_pending(&Session)` lets explicit human input outrank inbox wakes. Inbox dispatch should skip when it returns true, and also when the queue is paused.
- Web: `web/input-queue.js` provides the activity label (Model working / Running tool / Waiting for approval / Cancelling) and elapsed time. After replay or reconnect the start time is unknown, so it shows time "since reconnect". Animated dots are disabled under reduced motion, and the queue has 44px touch targets plus keyboard edit (Esc cancels, Ctrl/Cmd+Enter saves).
